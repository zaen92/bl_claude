# 사진 처리 방식 · JSON 내보내기/불러오기

## 1. 사진은 서버에 저장하지 않습니다
| 단계 | 사진 위치 | 저장 여부 |
|---|---|---|
| 업로드 | 브라우저에서 1400px·JPEG 82% 로 자동 압축 → **브라우저 메모리** | 저장 안 함 (새로고침하면 사라짐 — 기존 v3 와 동일) |
| AI 생성 | 생성 요청 본문에 포함 → Cloud Functions → Claude 로 전달해 분석 | 서버는 **전달만** 하고 Storage·Firestore·로그 어디에도 저장하지 않음 |
| 결과 | 본문의 `[사진1]`, `[사진2]` … 배치 + 캡션, 사진 장수(`imageCount`) | 텍스트만 Firestore 에 저장 |
| 생성 직후 미리보기 | 브라우저 메모리의 사진을 `[사진N]` 자리에 표시 | — |
| 저장 글·생성 이력·JSON 을 다시 열 때 | `[사진N]` 자리 표시만 ("왼쪽에서 사진을 업로드하세요") | 사용자가 왼쪽에서 사진을 **다시 첨부하면** 그 사진이 순서대로 미리보기에 표시 |

- 사진 한도(요청 기준): 최대 10장, 장당 약 1.5MB, 합계 약 9MB (Claude 로 보내기 위한 크기 제한이며 저장 용량 제한이 아님)
- 비용 분석용으로 **보낸 사진의 크기(바이트)** 와 장수만 관리자 전용 `generationMetrics` 에 기록
- Firebase **Cloud Storage 를 사용하지 않습니다** — 스테이징·운영 프로젝트에서 Storage 를 만들 필요가 없고, CORS·다운로드 토큰·사진 보관 정책·삭제 스케줄러·사용자별 용량 제한도 없습니다.
- 회원 탈퇴 시 삭제 대상: 저장 글·생성 기록·프로필 (사진은 원래 저장되지 않음)

### 보안·검증 장치
- Firestore 규칙: 저장 글(`posts`)은 텍스트 필드만 허용, 본문에 `data:image/…` 가 섞이면 거부
- 정적 테스트: Functions·웹 코드가 Storage 를 쓰지 않는지, 생성 기록에 사진 배열을 넣지 않는지 검사
- 통합·E2E 테스트: 생성 기록·비용 지표·저장 글·프로필·Firestore 쓰기 요청에 사진·Base64 가 없는지 확인

## 2. 기존 사진 데이터 마이그레이션 (임의 삭제하지 않음)
STEP 2~2.6 코드는 실제 배포된 적이 없으므로 **보통은 정리할 데이터가 없습니다.** 혹시 이전 코드를 배포해 사진이 저장된 프로젝트가 있다면:
1. 조회만 (아무것도 바꾸지 않음):
   ```bash
   npm run migrate:photos -- --project <프로젝트ID> --bucket <버킷 이름>
   ```
   생성 기록의 사진 필드, 저장 글의 사진 경로, `storageBytes`, 사진 삭제 작업 문서, Storage `users/` 아래 파일 수·용량을 보고합니다.
2. Firestore 의 사진 필드만 제거 (글 본문·생성 결과·`[사진N]` 배치는 유지, ⚠️ 되돌릴 수 없음):
   ```bash
   npm run migrate:photos -- --project <프로젝트ID> --apply-firestore
   ```
3. Storage 사진 파일 삭제 (⚠️ 되돌릴 수 없음 — 필요하면 먼저 `gcloud storage cp -r gs://<버킷>/users ./backup` 으로 백업):
   ```bash
   npm run migrate:photos -- --project <프로젝트ID> --bucket <버킷 이름> --delete-storage
   ```
4. 이후 Storage 를 쓰지 않으므로, Firebase 콘솔 → Storage → 규칙에서 모든 읽기·쓰기를 거부하거나 버킷을 비워 둘 수 있습니다.

## 3. JSON 내보내기·불러오기 (무료 · 로그인 불필요 · 서버 호출 없음)
> 원본 v3 와 STEP 2.6 까지는 JSON 내보내기 기능이 없었습니다. 요청 명세에 맞춰 최소한으로 추가했습니다 (ZIP·사진 포함 파일 없음).

- **내보내기**: 결과 화면 하단 `📤 JSON` → `jaeinit_post_<날짜-시각>.json` 다운로드 (파일 이름은 영문·숫자만 — 한글 파일 이름이 일부 브라우저에서 깨지는 문제 방지, 제목은 파일 안에 그대로)
- **불러오기**: 결과 화면 하단 또는 빈 결과 화면의 `📥 JSON 파일 불러오기` → 입력값(제목·메모·내용·장소 정보·글 유형·분량)과 생성 결과를 화면에 복원
  - 사진은 복원하지 않습니다. `[사진N]` 배치가 있으면 안내가 나오고, 필요하면 왼쪽에서 다시 첨부하면 미리보기에 표시됩니다.
  - 불러온 글은 💾 저장(무료)으로 계정에 저장할 수 있습니다.

### 파일 형식 (version 2)
```json
{
  "format": "jaeinit-blog-studio",
  "version": 2,
  "exportedAt": "2026-11-12T05:00:00.000Z",
  "createdAt": "2026-11-12T04:58:10.000Z",
  "style": { "preset": "jaeinit_v3", "label": "잰잇 여행블로그 기본 스타일" },
  "input": { "title": "", "memo": "", "content": "", "info": "", "type": "맛집", "volume": "normal", "imageCount": 3 },
  "result": { "title_1": "", "title_2": "", "title_3": "", "keyword_main": "", "keyword_sub": "", "keyword_location": "",
              "keyword_intent": "", "place_name": "", "place_address": "", "place_hours": "", "place_price": "",
              "body": "…[사진1]…", "hashtags": ["#…"], "reel": "", "thumbnail": "" },
  "photoLayout": { "count": 3, "maxIndex": 3, "markers": [{ "marker": "[사진1]", "index": 1, "line": 5 }], "note": "실제 사진은 포함되지 않습니다…" }
}
```
| 포함 | 제외 |
|---|---|
| 입력 원문·장소 정보, 글 유형·분량, SEO 제목 3개, 키워드, 본문, 해시태그, 릴스 대본, 썸네일 문구, 사진 배치 정보, 작성 스타일, 작성 일시 | 사진·Base64(문자열에 섞인 것도 제거), API 키, 인증 토큰, 크레딧 잔액, 관리자 권한, 결제 정보, uid·생성 ID 등 내부 식별자 |

- **작성 스타일**: 현재 앱에는 스타일 선택 기능이 없어 잰잇 기본 스타일(`jaeinit_v3`)이 고정으로 기록됩니다.
- **호환성**: 불러오기는 ① 위 v2 파일 ② 예전 v3 브라우저 저장 글 형식 `{id,title,type,date,data}` (단일 또는 배열 — 배열이면 첫 글) ③ 생성 결과 객체만 있는 JSON 을 지원합니다. 알 수 없는 필드는 모두 무시합니다.
- 파일 크기 1MB 제한, 잘못된 파일은 오류 안내만 하고 화면을 바꾸지 않습니다.
