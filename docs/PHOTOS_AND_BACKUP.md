# 사진 처리 방식 · JSON 내보내기/불러오기

## 1. 사진은 서버에 저장하지 않습니다
| 단계 | 사진 위치 | 저장 여부 |
|---|---|---|
| 업로드 | 브라우저에서 1400px·JPEG 82% 로 자동 압축 → **브라우저 메모리** (최대 10장, 사진 형식만, 원본 20MB 이하) | 저장 안 함 (새로고침하면 사라짐 — 기존 v3 와 동일) |
| 삭제·순서 변경 | 썸네일의 ✕ / ◀ ▶ — 번호(`[사진N]`)는 현재 순서대로 다시 매겨짐 | — |
| AI 생성 | 생성 요청 본문에 포함 → Cloud Functions → Claude 로 전달해 분석 | 서버는 **전달만** 하고 Storage·Firestore·로그 어디에도 저장하지 않음 |
| 결과 | 본문의 `[사진1]`, `[사진2]` … 배치 + 캡션, 사진 장수(`imageCount`) | 텍스트만 Firestore 에 저장 |
| 생성 직후 미리보기 | 브라우저 메모리의 사진을 `[사진N]` 자리에 표시 | — |
| 저장 글·생성 이력·JSON 을 다시 열 때 | `[사진N]` 자리 표시만 ("왼쪽에서 사진을 업로드하세요") | 사용자가 왼쪽에서 사진을 **다시 첨부하면** 그 사진이 순서대로 미리보기에 표시 |

- 사진 한도(요청 기준): 최대 10장, 장당 약 1.5MB, 합계 약 9MB (Claude 로 보내기 위한 크기 제한이며 저장 용량 제한이 아님)
- 비용 분석용으로 **보낸 사진의 크기(바이트)** 와 장수만 관리자 전용 `generationMetrics` 에 기록
- Firebase **Cloud Storage 를 사용하지 않습니다** — 스테이징·운영 프로젝트에서 Storage 를 만들 필요가 없고, CORS·다운로드 토큰·사진 보관 정책·삭제 스케줄러·사용자별 용량 제한도 없습니다.
- 회원 탈퇴 시 삭제 대상: 저장 글·생성 기록·프로필 (사진은 원래 저장되지 않음)

### 보안·검증 장치
- 저장 글(`posts`)은 서버 callable(`savePost`)로만 쓰며, 서버가 텍스트 필드만 남기고 `data:image/…`·긴 Base64·HTML 태그를 제거 (클라이언트 직접 쓰기는 규칙이 거부)
- 정적 테스트: Functions·웹 코드가 Storage 를 쓰지 않는지, 생성 기록에 사진 배열을 넣지 않는지 검사
- 통합·E2E 테스트: 생성 기록·비용 지표·저장 글·프로필·Firestore 쓰기 요청에 사진·Base64 가 없는지 확인

## 2. 기존 사진 데이터 마이그레이션 (임의 삭제하지 않음)
STEP 2~2.6 코드는 실제 배포된 적이 없으므로 **보통은 정리할 데이터가 없습니다.** 혹시 이전 코드를 배포해 사진이 저장된 프로젝트가 있다면:
1. 조회만 (아무것도 바꾸지 않음):
   ```bash
   npm run migrate:photos -- --project <프로젝트ID> --bucket <버킷 이름>
   ```
   생성 기록의 사진 필드, 저장 글의 사진 경로, `storageBytes`, 사진 삭제 작업 문서, Storage `users/` 아래 파일 수·용량을 보고합니다.
2. Firestore 의 사진 필드만 제거 (글 본문·생성 결과·`[사진N]` 배치는 유지, ⚠️ 되돌릴 수 없음):
   ```bash
   npm run migrate:photos -- --project <프로젝트ID> --apply-firestore
   ```
3. Storage 사진 파일 삭제 (⚠️ 되돌릴 수 없음 — 필요하면 먼저 `gcloud storage cp -r gs://<버킷>/users ./backup` 으로 백업):
   ```bash
   npm run migrate:photos -- --project <프로젝트ID> --bucket <버킷 이름> --delete-storage
   ```
4. 이후 Storage 를 쓰지 않으므로, Firebase 콘솔 → Storage → 규칙에서 모든 읽기·쓰기를 거부하거나 버킷을 비워 둘 수 있습니다.

## 3. JSON 내보내기·불러오기 (크레딧 없음 · 사진 미포함)
- **내보내기**: 결과 화면 하단 `📤 JSON` → 파일 내용 검증 → **서버 승인**(`authorizeExport`) → `jaeinit_<영문제목|post>_<날짜-시각>.json` 다운로드
  - FREE: **누적 5회**(운영 설정 `config/policy.freeExportLimit`, 월 초기화 없음) · PRO: 무제한. 화면에 `무료 내보내기 3 / 5회 사용` 표시
  - 응답이 끊겨 다시 눌러도 같은 승인 요청 ID 를 다시 보내므로 1회만 집계. 파일 검증 실패는 횟수를 쓰지 않음
  - 파일은 브라우저에서 만들어지므로 DRM 이 아닙니다(화면 복사까지 막지는 않음). 앱의 공식 내보내기 기능 사용 횟수를 서버에서 제한합니다.
  - 로그인·이메일 인증이 필요합니다(횟수를 계정에 기록하기 위해).
- **불러오기**: 모든 회원 **무제한** · 서버 호출·AI 호출·크레딧 없음. `📥 JSON 파일 불러오기` → 입력값(제목·메모·내용·장소 정보·글 유형·분량)·생성 결과·작성 스타일을 화면에 복원
  - 작성 중인 내용이 있으면 덮어쓰기 전에 확인합니다.
  - 사진은 복원하지 않습니다. `[사진N]` 배치가 있으면 안내가 나오고, 필요하면 왼쪽에서 다시 첨부하면 미리보기에 표시됩니다.
  - **불러오기 ≠ 계정 저장**: 불러온 글을 계정에 남기려면 💾 저장을 눌러야 하고, 이때 FREE 저장 개수 제한(5개)이 그대로 적용됩니다.

### 파일 형식 (version 3)
```json
{
  "format": "jaeinit-blog-studio",
  "version": 3,
  "exportedAt": "2026-11-12T05:00:00.000Z",
  "createdAt": "2026-11-12T04:58:10.000Z",
  "style": { "preset": "custom", "name": "내 여행 블로그", "blogName": "여행하는 곰", "greeting": "안녕하세요!", "closing": "감사합니다",
             "tone": "friendly", "useEmoji": true, "extra": "" },
  "input": { "title": "", "memo": "", "content": "", "info": "", "type": "맛집", "volume": "normal", "imageCount": 3 },
  "result": { "title_1": "", "title_2": "", "title_3": "", "keyword_main": "", "keyword_sub": "", "keyword_location": "",
              "keyword_intent": "", "place_name": "", "place_address": "", "place_hours": "", "place_price": "",
              "body": "…[사진1]…", "hashtags": ["#…"], "reel": "", "thumbnail": "" },
  "photoLayout": { "count": 3, "maxIndex": 3, "markers": [{ "marker": "[사진1]", "index": 1, "line": 5 }], "note": "실제 사진은 포함되지 않습니다…" }
}
```
`style.preset`: `basic`(기본 스타일 — `{preset, name}` 만), `jaeinit`(잰잇 기존 프롬프트), `custom`(사용자 스타일 스냅샷)

| 포함 | 제외 |
|---|---|
| 입력 원문·장소 정보, 글 유형·분량, SEO 제목 3개, 키워드, 본문, 해시태그, 릴스 대본, 썸네일 문구, 사진 배치 정보, 작성 스타일 설정, 작성 일시 | 사진·Base64(문자열에 섞인 것도 제거), API 키, 인증 토큰, 회원 등급, 크레딧 잔액·원장, 관리자 권한, 결제 정보, 내보내기 횟수, uid·생성 ID·스타일 문서 ID 등 내부 식별자 |

- **호환성**: 불러오기는 ① v3 ② v2 파일(`style.preset: "jaeinit_v3"` → 잰잇 스타일로 해석) ③ 예전 v3 브라우저 저장 글 형식 `{id,title,type,date,data}` (단일 또는 배열 — 배열이면 첫 글) ④ 생성 결과 객체만 있는 JSON 을 지원합니다.
- **검증**: 1MB 제한, JSON 구문·구조 검사, 허용된 필드만 받음(알 수 없는 필드·`plan`·`credits`·`exportCount` 등은 모두 버림), 문자열이 아닌 값 거부, HTML 태그·제어문자·이미지 Base64 제거. 화면에는 `textContent` 로만 표시하므로 악성 HTML 이 실행되지 않습니다. 잘못된 파일은 오류 안내만 하고 화면을 바꾸지 않습니다.

## 4. 크레딧 정책
| 작업 | 크레딧 |
|---|---|
| 새로운 AI 생성 | **1크레딧** (실패 시 자동 복구) |
| JSON 내보내기 · 불러오기 | 크레딧 없음 (FREE 내보내기는 누적 5회 제한, 불러오기 무제한) |
| 글 저장 · 삭제 · 저장된 글 확인 · 생성 이력 보기 | 크레딧 없음 (FREE 저장 5개 제한) |
| 본문 수정(✏️ 수정) · 복사 | 크레딧 없음 — 저장된 글을 고쳐 다시 저장하면 같은 글이 수정되고 개수는 늘지 않음 |
| 사진 업로드·삭제·순서 변경·미리보기 | 크레딧 없음 |
| 작성 스타일 저장·수정 | 크레딧 없음 (FREE 1개) |
