# 사진 보관 정책 & 비용

## 흐름
1. 브라우저가 사진을 1400px·JPEG 82% 로 압축 (기존 v3 와 동일, 보통 장당 200~500KB)
2. `generatePost` 요청에 포함 → 서버가 검증(최대 10장, 장당 ≈1.5MB, 합계 ≈9MB) 후
   `users/{uid}/generations/{generationId}/photo_{n}.jpg` 로 저장 (Admin SDK, 클라이언트 직접 업로드 불가)
3. 같은 사진을 Claude 에 base64 로 전달 → 본문 `[사진N]` 위치 배치
4. `generations.photos` · 저장 글 `posts.photos` 에 경로 기록 → 다시 열면 Storage 에서 불러와 미리보기에 표시
5. 생성 실패 시 업로드한 사진을 즉시 삭제하고 용량을 반환

## 보안
- `storage.rules`: `users/{uid}/**` 는 본인(또는 admin claim) 만 읽기, **쓰기는 모두 거부** (서버만 저장)
- 화면 표시는 `getDownloadURL` (다운로드 토큰 URL). URL 을 아는 사람은 열람 가능하므로 공유하지 않도록 안내 필요.
  토큰은 Firebase 콘솔에서 파일별로 폐기할 수 있음.

## 사용자별 용량 제한
- `users.storageBytes` 를 서버가 예약 트랜잭션에서 증가/실패 시 감소
- 상한 `STORAGE_QUOTA_MB` (기본 200MB ≈ 사진 400~1,000장). 초과 시 생성 전 거부(크레딧 차감 없음)

## 보관 기간 (현재 정책 / 결정 필요)
- 현재: 계정이 있는 동안 보관 (저장 글을 지워도 생성 이력이 사진을 참조하므로 유지)
- 권장 (다음 단계): 저장하지 않은 생성 건의 사진은 90일 후 삭제하는 스케줄 함수 + 회원 탈퇴 시 전체 삭제

## 예상 비용 (Cloud Storage, 서울 `asia-northeast3` 표준 스토리지 기준 — 2026-11 정가는 콘솔에서 재확인 필요)
| 가정 | 값 |
|---|---|
| 생성 1회 평균 사진 | 5장 × 350KB ≈ 1.75MB |
| 월 생성 1,000회 | ≈ 1.75GB 증가/월 |
| 12개월 누적 | ≈ 21GB |

- 저장: GB-월 약 $0.023~0.03 수준 → 21GB 누적 시 **월 약 $0.5~0.7**
- 다운로드(egress): 저장 글을 다시 열 때 발생. 1,000회 × 1.75MB ≈ 1.75GB → 월 $0.2 내외
- 작업(쓰기/읽기) 요청: 월 수천~수만 건 → 수 센트 수준
- Firebase 무료 한도(Spark: 5GB 저장, 1GB/일 다운로드)는 Blaze 요금제에서도 기본 버킷에 적용되는 무료 사용량이 있음

→ 사진 비용은 AI 호출 비용(회당 약 $0.1 내외, [AI_COST.md](AI_COST.md))보다 훨씬 작습니다.
